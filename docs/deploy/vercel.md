# Развёртывание на Vercel

Приложение работает как одна serverless-функция Vercel (`api/index.ts`, Express) и статический SPA (`web/dist`) на CDN
Vercel. База данных — Neon, её подготовка описана в [neon.md](neon.md). Настройки сборки, регион (`fra1`), rewrites,
заголовки безопасности и Vercel Cron лежат в `vercel.json`, в консоли их повторять не нужно.

## Шаги

1. Подготовить БД на Neon по [neon.md](neon.md) (шаги 1–6) и взять pooled-строку подключения роли `gpu_rent_web`.
2. В Vercel: Add New, Project, импортировать репозиторий `hosjpps/gpu-rent`. Корень проекта — корень репозитория,
   Framework Preset — Other (в `vercel.json` `framework: null`), команды сборки и каталог вывода берутся из `vercel.json`.
   Версия Node (24.x) берётся из `engines` в корневом `package.json`.
3. До первого деплоя задать переменные окружения (Settings, Environment Variables), см. таблицу ниже. Пароли и ключи
   генерируются заново и в репозиторий не попадают: `ENC_KEY`, `WEBHOOK_SECRET`, `CRON_SECRET` — например,
   `openssl rand -base64 32`; пароль роли `gpu_rent_web` — `openssl rand -hex 24` (без спецсимволов: он вставляется в
   `DATABASE_URL`, а `/`, `+`, `=`, `#`, `@` из base64 ломают разбор адреса, и приложение отвечает 500 на любой запрос к БД).
   Если пароль со спецсимволами всё же есть, в адресе его нужно закодировать (`/` -> `%2F`, `+` -> `%2B`, `=` -> `%3D`,
   `#` -> `%23`, `@` -> `%40`); то же касается `secrets.DATABASE_URL_DIRECT`.
4. Deploy. Проверить: `GET <адрес>/api/health` отвечает без обращения к БД, `GET <адрес>/api/health?deep=1` возвращает
   `"db":"ok"` (будит Neon), затем вход под demo и `GET /api/catalog/gpus`.

## Переменные окружения

| Переменная | Нужна | Значение |
|---|---|---|
| `DATABASE_URL` | да | pooled-адрес Neon (хост с `-pooler`), роль `gpu_rent_web`, `?sslmode=require` |
| `ENC_KEY` | да | ключ шифрования переменных окружения инстансов, не короче 16 символов |
| `WEBHOOK_SECRET` | да | секрет подписи уведомлений платёжного шлюза, не короче 16 символов |
| `CRON_SECRET` | да, если нужен биллинг по расписанию | не короче 16 символов. Без него `/api/internal/billing` в production отвечает 503, биллинг идёт только «при обращении» пользователя. Vercel Cron сам передаёт эту переменную как `Authorization: Bearer` |
| `APP_URL` | желательно | адрес сайта без слэша (`https://….vercel.app`): ссылки подтверждения email и оплаты, разрешённый Origin. Не задан: берётся Host запроса |
| `ALLOWED_ORIGINS` | нет | дополнительные разрешённые Origin через запятую |
| `DEMO_MAIL`, `DEMO_PAYMENTS` | нет | см. раздел ниже, по умолчанию выключены |
| `DB_POOL_MAX` | нет | по умолчанию 2; на Neon число соединений ограничено |

Полный список с комментариями — корневой `.env.example` (локально копируется в `server/.env`).

## Демо-режимы

Кода отправки писем в проекте нет, платёжный шлюз только демонстрационный. Поэтому в production без `DEMO_MAIL=1` и
`DEMO_PAYMENTS=1`:

- новый пользователь не может подтвердить email, а без подтверждения нельзя запускать инстансы (`EMAIL_NOT_VERIFIED`);
- пополнить баланс нельзя: `POST /api/payments/:id/demo-pay` отвечает 404.

Запускать инстансы смогут только заранее подтверждённые `demo` и `admin` из `seed_demo.sql`. Для учебной демонстрации
оба режима можно включить осознанно: тогда ответ API содержит ссылку подтверждения email или оплаты, а баланс
пополняется без реальных денег. Для настоящей эксплуатации режимы выключены, и нужны почтовый провайдер и платёжный шлюз.

## GitHub Actions

Workflows в `.github/workflows`; значения задаются в Settings, Secrets and variables, Actions.

| Что | Где | Для чего |
|---|---|---|
| `vars.APP_URL` | Variables | адрес сайта без слэша; нужен `billing-cron.yml` и `uptime.yml`, без него они пропускают шаг |
| `secrets.CRON_SECRET` | Secrets | то же значение, что `CRON_SECRET` на Vercel; `billing-cron.yml` каждые 30 минут вызывает `POST /api/internal/billing` |
| `secrets.DATABASE_URL_DIRECT` | Secrets | direct-адрес Neon (не пулер) для `db-backup.yml`; direct-строка владельца проекта (как для миграций) или роль с BYPASSRLS; роль только с `pg_read_all_data` не годится: на таблицах включён RLS, и `pg_dump` падает. Без него копия не делается |
| `secrets.BACKUP_PASSPHRASE` | Secrets | парольная фраза шифрования дампа; репозиторий публичный, без неё дамп проверяется, но в артефакт не загружается |

Логи Actions публичного репозитория видны всем, поэтому workflows не печатают суммы списаний и секреты.
